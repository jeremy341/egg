# Finish setup after first boot

Egg is running, but a fresh instance has no password, no deploy target and no integrations. Work through this list once, in order, after the first boot. Each item links to the full guide; the linked docs are the source of truth if a screen or default has changed.

Back to the [self-hosting guide](README.md). For the name, colours, ports and build memory, see [customising.md](customising.md).

1. [ ] **Set a password.** In local mode the first sign-in asks for the recovery key from the private `.env.local` (`LOCAL_MODE_SECRET`) and a password of at least 12 characters. Keep both private: anyone with the recovery key can set or reset the password. With Hack Club sign-in there is no local password; set up the Hack Club app instead if that is how people will sign in. See [Run without Hack Club](README.md#run-without-hack-club), [How sign-in works](README.md#how-sign-in-works) and [Hack Club Auth](../backend-setup.md#hack-club-auth).

2. [ ] **Connect a Nest server.** On the Projects page, connect a server and enter your Nest username, then paste the public key Egg shows into the SSH Keys page of the Nest dashboard. Leave `NEST_HOST` and `NEST_PORT` at their defaults (`hackclub.app` and `22`) for Nest. For a server you own, set both in `.env.local` before you add the server, since each server keeps the host and port it had when created. You can connect up to 5 servers per account. See [Connect a server to deploy to](README.md#connect-a-server-to-deploy-to), [On Hack Club Nest](README.md#on-hack-club-nest) and [On a server you own](README.md#on-a-server-you-own). The in-app guide is at `/docs/servers`.

3. [ ] **Confirm the host key.** The first **Test connection** only reads the server's host key, hangs up and shows its fingerprint. Compare that fingerprint with the one Nest shows (on your own server, `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub`) before pressing **Confirm host key**. Egg pins that key and refuses any other; it sends nothing to the server until you confirm. A later "The host key of ... changed" error means disconnect, add the server again and confirm the new fingerprint, not confirm the old one again. See [Connect a server to deploy to](README.md#connect-a-server-to-deploy-to), [Servers and repositories](README.md#servers-and-repositories) and [Security notes](../backend-setup.md#security-notes).

4. [ ] **Enable only the container permissions you need.** **Terminal**, **File changes** and **Removing leftovers** start off for every new server, and local mode does not change that. The terminal is a root shell on the container, so leave all three off until a task needs one, and turn each on only on the servers that need it. Turning Terminal or File changes on asks you to type the server name and needs a fresh sign-in when Hack Club is set up; turning a switch off never does. See [Permission switches are off by default](README.md#permission-switches-are-off-by-default), [Confirming again](README.md#confirming-again-reauth) and the in-app `/docs/container#container-switches`.

5. [ ] **Set up the GitHub App, but only if you need private repositories.** Public repositories deploy by URL without it. You need the App for private repositories, the repository picker, deploy on push and pull request previews. Create it at `github.com/settings/apps/new`: callback and setup URL `<APP_URL>/api/github/callback`, webhook URL `<APP_URL>/api/webhooks/github` with a secret saved as `GITHUB_WEBHOOK_SECRET`, Contents and Metadata read-only, Pull requests read and write, and Push and Pull request events. Generate a private key and put the five required values in `.env.local`, then restart Egg. GitHub must be able to reach the webhook address; a tunnel normally exposes your whole site, including the login page. See [Set up the GitHub App](README.md#set-up-the-github-app), [Create the App](README.md#create-the-app), [Webhooks need an address GitHub can reach](README.md#webhooks-need-an-address-github-can-reach) and [GitHub App](../backend-setup.md#github-app).

6. [ ] **Configure backups.** Egg's data is in one SQLite file, `web/data/egg.db` locally or `/data/egg.db` under Compose. For a consistent copy, stop Egg and copy the file (and any `egg.db-wal` / `egg.db-shm` files beside it), or use `sh deploy/backup.sh` / `pnpm run backup` on a server to copy it while Egg runs; the script gzips into `backups/` and keeps the newest 14 (`BACKUP_KEEP`). Back up `.env.local` (setup A) or `.env` (setup B) separately, and store it apart from the database: sealed SSH keys need `APP_SECRET`, and local mode needs `LOCAL_MODE_SECRET` to reset a password. These backups do not cover persistent data your apps write on the deploy target. See [Backups](README.md#backups), [Backup](README.md#backup) and the in-app `/docs/selfhost#selfhost-database`.

7. [ ] **Turn on a status page and notifications.** These are for watching apps after they are live, not for the first deploy. Uptime checks run every five minutes; in a project's Settings, publish the **Public Status Page** to get a page at `<APP_URL>/status/<key>` showing the project name and 30 days of uptime, and paste a Discord or Slack incoming webhook URL into **Notifications**, then use **Send test message**. Only plain `https` Discord/Slack webhook URLs are accepted; the URL is stored encrypted and never shown again. See the in-app guides `/docs/status-page`, `/docs/notifications` and `/docs/monitoring#monitoring-uptime`, plus [Notifications and alerts](../backend-setup.md#security-notes) and the detailed [Status page](../design/feature-inventory.md#status-page), [Notifications (webhook)](../design/feature-inventory.md#notifications-webhook) and [Alerts](../design/feature-inventory.md#alerts) reference.

8. [ ] **Secure the instance.** Use HTTPS and expose only your proxy (ports 80 and 443), never the app port; set `TRUST_PROXY=1` only when every request reaches Egg through that proxy. Do not set Hack Club keys alongside local mode, and put a public instance behind your own access control: `LOCAL_MODE_ALLOW_REMOTE=1` puts the sign-in form on the network and belongs behind a VPN or access proxy. Keep the database and `APP_SECRET` apart in backups, and rotate any variable a public static deployment may have served as `/.env`. Optionally set `SECURITY_REPORT_ADMIN_ID` to your user id (from `/api/me`) to enable the private report inbox and `/admin`. See [Security notes](README.md#security-notes), [Before you open Egg beyond localhost](README.md#before-you-open-egg-beyond-localhost), [Private vulnerability inbox](README.md#private-vulnerability-inbox), [Instance administration and maintenance](README.md#instance-administration-and-maintenance) and the known gaps in [self-host-gaps.md](../design/self-host-gaps.md).
