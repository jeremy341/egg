# Docker target adapter foundation

The Docker target module is an internal contract, not an available deployment mode. Native applications continue to use systemd. No Docker daemon or control-plane socket is accessed by this foundation, and Docker on Nest LXC has not been validated.

An implementation must run its checks and operations on the intended target. It must establish engine access, nesting, enforceable cgroup limits, sufficient disk and port mapping; Compose additionally requires Compose support. Unknown results are rejected. These booleans represent verified facts for the requested release, not installation detection alone. Resource thresholds, versions and Nest policy must be determined by the integrating implementation.

A candidate is prepared and checked while the active release serves. Activation requires an atomic routing switch or a verified restoration of the previous route. If the activation outcome is uncertain, reconcile the target before further cleanup; the orchestration intentionally does not discard it. Candidate cleanup must be project- and release-scoped and must preserve persistent data. Rollback of application code cannot undo database migrations or external writes. A target implementation must additionally provide bounded build and health timeouts, authenticated secret delivery without logs, status/log collection, image retention, port allocation and safe rollback. These are not implemented here.

The Compose validator accepts only an already parsed, narrowly defined object: services with optional image, loopback-only explicit TCP port mappings, and declared named volumes. It rejects other fields, bind mounts, interpolation and Compose extensions. The integration must reject unsafe YAML parsing features, validate before any target mutation and execute only a canonical representation derived from validated values, never the original YAML. Named volumes need stable project-scoped names outside release folders; deletion must preserve data by default. This subset does not yet support dependencies, health checks, build definitions or full Compose semantics.

Before exposing this mode, test the actual target transport, candidate isolation and routing, crashes and ambiguous activation recovery, permissions, limits, cleanup and rollback on real Nest and self-hosted Linux targets. Docker daemon access grants powerful target privileges and does not imply isolation between projects.
